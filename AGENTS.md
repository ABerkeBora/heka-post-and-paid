## Product and payment boundaries

A brand funds one immutable post agreement. A bounded procurement agent buys the pinned TwitterAPI snapshot and submits its exact signed bytes; the contract pays only the fixed creator once. Pin signer, operation, parameters, projection, post/author IDs, campaign substring, publication window, response age and deadline before funding. Derive the request hash in the contract. Missing or invalid data never releases collateral.

Use only Base Sepolia test assets. API aUSD fees, native test ETH collateral and gas are separate costs. No mainnet value, new paid services, automatic top-ups or third-party messages. Test wallets belong in ignored 0600 files. Never expose private keys, recovery phrases or unconsumed payment authorizations in logs, prompts or public files. Model proposals have no keys or arbitrary transaction authority.

Persist mandates/intents, reservations and signed transaction hashes before side effects. Reconcile chain receipts and token authorizations before retries; never create a second authorization for an unresolved intent. App budget checks are not on-chain permissions. Account for Base L1/operator fees and disclose that the total fee preflight is an estimate.

A signed snapshot authenticates the provider response. It does not establish continuous publication, advertising quality, legal compliance, independent truth or social-account ownership of the beneficiary wallet. The historical public post scenario is a test agreement, not an actual commissioned advertisement.
